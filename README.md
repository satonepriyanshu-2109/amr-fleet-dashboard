AMR Fleet Dashboard
Real-time web dashboard for monitoring and managing a simulated fleet of Autonomous Mobile Robots (AMRs) in a smart warehouse.

This is the software/dashboard prototype for:

SIH26123 — Edge-AI Based Distributed Fleet Coordination for Autonomous Mobile Robots (AMRs) in Smart Warehouses

Current prototype: The dashboard currently uses simulated robot telemetry generated by the Python backend. ROS 2 integration and the real occupancy-grid map are planned next. You can run the current prototype without ROS 2.

1. What This Project Does
The dashboard provides a web interface for:

Monitoring multiple AMRs in real time

Viewing robot positions on a warehouse map

Monitoring battery and robot status

Creating warehouse tasks through a Manager interface

Viewing task history

Receiving live robot telemetry using WebSockets

Preparing the dashboard for future ROS 2 integration

3. Manager Task Concept
The Manager section is a supervisory control interface.

During normal operation, task allocation is intended to remain decentralized among the autonomous fleet.

The manager creates an objective such as:

Pickup:      A1
Destination: B3
Priority:    HIGH
The dashboard sends this to the backend:

Manager
   |
   v
React Dashboard
   |
   | POST /api/tasks
   v
FastAPI
   |
   v
Task
Example task:

{
  "task_id": "TASK_001",
  "pickup": "A1",
  "destination": "B3",
  "priority": "HIGH",
  "status": "PENDING"
}
Later, this task request will be connected to the ROS 2 fleet coordination layer.

Why the Manager interface exists
It provides human supervision for situations such as:

Urgent tasks

Robot failures

Operational intervention

Safety-related intervention

Priority changes

The manager does not need to continuously select an individual robot during normal decentralized operation.

28. Troubleshooting
Problem: python is not recognized
Install Python and make sure Python is added to PATH.

Check:

python --version
Expected:

Python 3.x.x
Problem: pip is not recognized
Use:

python -m pip
instead of:

pip
For example:

python -m pip install -r requirements.txt
Problem: uvicorn is not recognized
Use:

python -m uvicorn main:app --reload
instead of:

uvicorn main:app --reload
Problem: ModuleNotFoundError: No module named 'fastapi'
Make sure the virtual environment is activated:

.\venv\Scripts\activate
Then install:

python -m pip install -r requirements.txt
Problem: ModuleNotFoundError: No module named 'uvicorn'
Run:

python -m pip install uvicorn
Problem: WebSocket library error
Install:

python -m pip install websockets
Or reinstall all backend requirements:

python -m pip install -r requirements.txt
Problem: React cannot connect to FastAPI
Check that Terminal 1 is running:

http://127.0.0.1:8000
Then check that Terminal 2 is running:

http://localhost:5173
Also check the browser developer console for errors.

Problem: Dashboard shows no robot updates
Check that FastAPI is running.

Then refresh the React page.

The WebSocket should connect automatically to:

ws://127.0.0.1:8000/ws/fleet
Problem: Manager task does not get created
Check:

http://127.0.0.1:8000/docs
Then test:

POST /api/tasks
If Swagger successfully creates the task, the backend is working.

Problem: Port 8000 is already in use
Stop the previous FastAPI process or use another port.

Example:

python -m uvicorn main:app --reload --port 8001
If you change the backend port, remember that the React WebSocket/API URLs must also be updated.

Problem: Port 5173 is already in use
Vite may automatically select another available port.

Check the terminal output for the actual URL.
