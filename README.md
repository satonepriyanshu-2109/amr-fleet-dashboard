# AMR Fleet Dashboard

Real-time web dashboard for monitoring and managing a simulated fleet of Autonomous Mobile Robots (AMRs) in a smart warehouse.

This project is the software/dashboard prototype for:

**SIH26123 — Edge-AI Based Distributed Fleet Coordination for Autonomous Mobile Robots (AMRs) in Smart Warehouses**

> **Current prototype:** The dashboard currently uses simulated robot telemetry generated by the Python backend. ROS 2 integration and the final occupancy-grid map are planned next.

---

## 1. What This Project Does

The dashboard provides a web interface for:

- Monitoring multiple AMRs in real time
- Viewing robot positions on a warehouse map
- Monitoring battery and robot status
- Creating warehouse tasks through a Manager interface
- Viewing task history
- Receiving live robot telemetry using WebSockets
- Preparing the dashboard for future ROS 2 integration

# 3. Manager Task Concept

The Manager section is a **supervisory control interface**.

During normal operation, robot-level task allocation is intended to remain decentralized among the autonomous fleet.

The manager creates an objective such as:

```text
Pickup:       A1
Destination:  B3
Priority:     HIGH
```

The dashboard sends this task to the backend:

```text
Manager
   |
   v
React Dashboard
   |
   | POST /api/tasks
   v
FastAPI
   |
   v
Task
```

Example:

```json
{
  "task_id": "TASK_001",
  "pickup": "A1",
  "destination": "B3",
  "priority": "HIGH",
  "status": "PENDING"
}
```

Later, this task request will be connected to the ROS 2 fleet coordination layer.

### Why the Manager Interface Exists

It can be used for:

- Urgent tasks
- Robot failures
- Operational intervention
- Safety-related intervention
- Priority changes

The manager does **not** continuously select an individual robot during normal decentralized operation.

# 28. Troubleshooting

## Python is not recognized

Check:

```powershell
python --version
```

If Python is not installed, install Python and make sure it is added to PATH.

---

## pip is not recognized

Use:

```powershell
python -m pip
```

instead of:

```powershell
pip
```

For example:

```powershell
python -m pip install -r requirements.txt
```

---

## Uvicorn is not recognized

Use:

```powershell
python -m uvicorn main:app --reload
```

instead of:

```powershell
uvicorn main:app --reload
```

---

## `ModuleNotFoundError: No module named 'fastapi'`

Make sure the virtual environment is activated:

```powershell
.\venv\Scripts\activate
```

Then install dependencies:

```powershell
python -m pip install -r requirements.txt
```

---

## `ModuleNotFoundError: No module named 'uvicorn'`

Run:

```powershell
python -m pip install uvicorn
```

---

## WebSocket library error

Run:

```powershell
python -m pip install websockets
```

Or reinstall everything:

```powershell
python -m pip install -r requirements.txt
```

---

## React cannot connect to FastAPI

First check that Terminal 1 is running:

```text
http://127.0.0.1:8000
```

Then check Terminal 2:

```text
http://localhost:5173
```

Also check the browser Developer Console for errors.

---

## Dashboard shows no robot updates

Make sure FastAPI is running.

Then refresh the React page.

The frontend should connect automatically to:

```text
ws://127.0.0.1:8000/ws/fleet
```

---

## Manager task does not get created

Open:

```text
http://127.0.0.1:8000/docs
```

Test:

```text
POST /api/tasks
```

If Swagger successfully creates the task, the backend is working.

---

## Port 8000 is already in use

Stop the previous FastAPI process or use another port:

```powershell
python -m uvicorn main:app --reload --port 8001
```

If you change the backend port, update the API and WebSocket URLs in the React frontend as well.

---

## Port 5173 is already in use

Vite may automatically select another available port.

Check the terminal output for the actual URL.

# 32. Development Rules

## Keep Frontend Independent From ROS 2

React should communicate with the backend.

Do not put ROS 2 logic directly inside React.

Preferred:

```text
ROS 2
 |
 v
Python
 |
 v
FastAPI
 |
 v
React
```

Not:

```text
ROS 2
 |
 v
React
```

---

## Keep Manager Separate From Decentralized Allocation

The Manager creates objectives.

The decentralized fleet coordination layer should make robot-level decisions during normal operation.

This preserves the intended architecture of the SIH problem.
